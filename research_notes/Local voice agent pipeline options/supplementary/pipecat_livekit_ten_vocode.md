# Research Summary: Open-Source Real-Time Conversational Voice Agent Frameworks

**Caveat on dates:** Automated page summarization returned inconsistent years for some release timestamps (e.g., one fetch rendered Pipecat's v1.15.0 as "October 29, 2024" while PyPI metadata and TEN's release list correctly reflect 2026 dates). Treat specific day-level dates below as approximate; version numbers and relative cadence (e.g., "weekly/biweekly releases") are more reliable than the exact calendar dates attached to them.

## 1. Pipecat (pipecat-ai/pipecat)

- **Repo/stars/license/language:** github.com/pipecat-ai/pipecat — ~16.9k stars, BSD-2-Clause license, Python. [Source](https://github.com/pipecat-ai/pipecat)
- **Maintenance:** 14,728+ commits on main; latest PyPI version is 1.15.0 (pipecat-ai package supports Python 3.11–3.14). Release notes show a rapid, roughly weekly cadence (v1.10.0 → v1.15.0 in close succession). [Source](https://github.com/pipecat-ai/pipecat/releases) [Source](https://pypi.org/pypi/pipecat-ai/json)
- **Company backing / community:** Maintained by Daily.co with the community; repo description states "Maintained by Daily and the community." Reported ~220 contributors, ~2,000 forks (per a secondary search summary, not independently re-verified against the live contributor graph). Discord at discord.gg/pipecat with a #community-integrations channel. [Source](https://github.com/pipecat-ai/pipecat) [Source](https://github.com/pipecat-ai/pipecat/blob/main/COMMUNITY_INTEGRATIONS.md)
- **Transports:** Daily (WebRTC), **SmallWebRTC** (self-contained, dependency-free, peer-to-peer WebRTC transport intended for local dev/self-hosting — "default in all Pipecat quickstart templates, no account needed"), LiveKit, FastAPI WebSocket, Vonage, WhatsApp. [Source](https://docs.pipecat.ai/client/concepts/choosing-a-transport) [Source](https://reference-server.pipecat.ai/en/latest/api/pipecat.transports.smallwebrtc.transport.html)
- **Local STT:** `WhisperSTTService` (offline, multiple model sizes, CPU/CUDA/Apple Silicon via MLX acceleration); `MoonshineSTTService` (offline, ONNX Runtime, CPU-only, no API key). [Source](https://docs.pipecat.ai/api-reference/server/services/stt/whisper) [Source](https://docs.pipecat.ai/api-reference/server/services/stt/moonshine)
- **Local TTS:** `KokoroTTSService` (kokoro-onnx, fully local/offline, auto-downloads models to `~/.cache/pipecat/kokoro-onnx/`), `PiperTTSService` (maintained, latency/concurrency-optimized), `XTTSService` (Coqui XTTS via locally hosted streaming server — **deprecated, to be removed in 2.0.0**). [Source](https://docs.pipecat.ai/api-reference/server/services/tts/kokoro) [Source](https://docs.pipecat.ai/server/services/tts/xtts)
- **VAD/turn detection:** Silero VAD built in; **Smart Turn** ML-based end-of-turn model — `LocalSmartTurnAnalyzerV3` runs locally via ONNX, ~8M params (Whisper-Tiny based, int8 quantized), no GPU required, 23 languages, weights bundled with the core package (no separate download). As of v0.0.102, `TurnAnalyzerUserTurnStopStrategy` with `LocalSmartTurnAnalyzerV3` is the default turn-stop strategy. There's also a `local_coreml_smart_turn` variant implying native Apple Silicon (CoreML) support. [Source](https://docs.pipecat.ai/api-reference/server/utilities/turn-detection/smart-turn-overview) [Source](https://reference-server.pipecat.ai/en/stable/api/pipecat.audio.turn.smart_turn.local_coreml_smart_turn.html) [Source](https://www.daily.co/blog/announcing-smart-turn-v3-with-cpu-inference-in-just-12ms/)
- **LLM architecture / pluggability:** Base class `LLMService` handles function-calling registration/execution; concrete services (e.g., `OLLamaLLMService`, `CerebrasLLMService`, `OpenPipeLLMService`) subclass `OpenAILLMService` or `LLMService` directly, showing a documented pattern for writing a fully custom LLM backend (not limited to OpenAI-compatible HTTP). A custom pipeline/processor can also wrap the LLM step. `LLMWorker` accepts any `LLMService` instance plus `@tool`-decorated functions. [Source](https://reference-server.pipecat.ai/en/stable/api/pipecat.services.llm_service.html) [Source](https://reference-server.pipecat.ai/en/stable/_modules/pipecat/services/ollama/llm.html) [Source](https://docs.pipecat.ai/api-reference/server/workers/llm-worker)
- **Interruption/barge-in:** Documented "Interruptions" fundamentals — when VAD/Smart Turn detect the user speaking over the bot, the bot stops immediately, in-flight work (LLM/TTS generation) is cancelled, and the pipeline resets for new input; exposed as a configurable interruption strategy with interrupt hooks for flushing the TTS buffer. [Source](https://docs.pipecat.ai/pipecat/fundamentals/interruptions)
- **Filler/background speech:** Filler and "thinking" audio frames are a documented pattern for instant acknowledgement during longer processing, discussed alongside Smart Turn end-of-turn and interruption handling as core pipeline components. [Source](https://docs.pipecat.ai/pipecat/fundamentals/interruptions)
- **macOS/Apple Silicon:** MLX Whisper STT explicitly requires macOS on Apple Silicon (arm64) and will not run on Intel Macs; a CoreML-based Smart Turn analyzer variant (`local_coreml_smart_turn`) exists, implying native Apple Silicon acceleration path for turn detection as well. [Source](https://reference-server.pipecat.ai/en/stable/api/pipecat.audio.turn.smart_turn.local_coreml_smart_turn.html)
- **Client options:** JS, React, React Native (iOS/Android), native Swift (iOS), native Kotlin (Android), and C++ SDKs, all implementing the RTVI (Real-Time Voice and Video Inference) standard; handle mic/camera access, audio playback, transport, and bot event stream. [Source](https://docs.pipecat.ai/client/introduction)

## 2. LiveKit Agents (livekit/agents)

- **Repo/stars/license/language:** github.com/livekit/agents — ~15.0k stars (one search result cited 14,963 stars/4,004 forks), Apache-2.0, Python (plus a Node.js SDK). [Source](https://github.com/livekit/agents)
- **Maintenance:** 4,357+ commits; PyPI shows versioned releases up through at least livekit-agents 1.8.9/1.8.10, with a dense release cadence (multiple point releases per month across Sept–Oct in the release history fetched). [Source](https://github.com/livekit/agents/releases) [Source](https://pypi.org/pypi/livekit-agents/json)
- **Company backing/community:** Backed by LiveKit, Inc. (venture-funded; raised a Series B per LiveKit's own blog). Active Discord and GitHub community cited generally, though exact Discord member count was not found in available sources. [Source](https://blog.livekit.io/livekits-series-b/) [Source](https://github.com/livekit/agents)
- **Self-hosting:** LiveKit media server, SIP service, egress, ingress, the Agents framework, and all client SDKs are all Apache-2.0 and self-hostable with full feature parity vs. LiveKit Cloud; agents run as containers on your own Kubernetes. [Source](https://livekit.com/blog/best-open-source-voice-and-video-ai-agent-frameworks)
- **Transports:** LiveKit room-based WebRTC (self-hosted or Cloud), WebSocket data channels, native desktop/mobile audio via client SDKs, and a full SIP telephony stack (inbound/outbound calls bridged into rooms as special participants, tested with Twilio, Telnyx, Exotel, Plivo, Wavix, Sinch, didlogic, DIDWW; supports DTMF, SIP REFER). [Source](https://docs.livekit.io/telephony/agents-integration/) [Source](https://docs.livekit.io/telephony/)
- **Local STT/TTS:** Searches surfaced primarily hosted-provider plugins (Deepgram, Cartesia, Google, Microsoft, Sarvam, Nabrah, etc.); I did not find explicit, documented first-party local/self-hosted STT or TTS engine integrations (e.g., whisper.cpp, Piper, Kokoro) comparable to Pipecat's. **This should be flagged as an open gap** — LiveKit Agents' plugin ecosystem appears weighted toward cloud API providers, with local inference concentrated in VAD/turn-detection rather than STT/TTS. (Not fully confirmed; worth a follow-up check against the official plugins list.)
- **VAD/turn detection:** Built-in inference-based VAD. **Turn-detector plugin** (`livekit-plugins-turn-detector`) ships local, CPU-runnable semantic models: an English model (~200MB RAM, ~10ms inference) and a multilingual model (~400MB RAM, ~25ms inference, 13 languages). For self-hosted/non-Cloud deployments, the default is **v1-mini**, a lightweight model running locally in a shared CPU process (<500MB RAM). [Source](https://pypi.org/project/livekit-plugins-turn-detector/) [Source](https://docs.livekit.io/agents/logic/turns/turn-detector/)
- **LLM architecture/pluggability:** `livekit.agents.llm` module defines the LLM abstraction; documentation and API reference exist for building custom LLM integrations, and an open GitHub issue (#7105) requests support for pluggable **custom interruption detectors**, implying the LLM/turn pipeline is already modular at the plugin level but some detection logic is still provider-fixed pending that feature. [Source](https://docs.livekit.io/reference/python/livekit/agents/llm/index.html) [Source](https://github.com/livekit/agents/issues/7105)
- **Interruption/barge-in:** `InterruptionOptions.mode` supports `"vad"` (VAD-based) and `"adaptive"` (LiveKit's semantic/adaptive detection) interruption strategies; a documented "Uninterruptable Agent" recipe shows interruption can be disabled; custom interruption detectors are a requested-but-not-yet-shipped feature (#7105). [Source](https://docs.livekit.io/reference/recipes/uninterruptable/) [Source](https://livekit.com/blog/turn-detection-and-interruption-handling)
- **Filler/background speech:** Documented, first-class support — "preemptive generation" speculatively starts LLM response before end-of-turn confirmation (TTS still waits); a "filler scope" API lets you wrap a long-running operation so a filler utterance plays only once the session has been continuously idle for a configured delay (never talks over the user or stacks behind other speech); `RunContext` exposes `session.say()` to push filler audio directly, bypassing the LLM; async/background tool execution pattern lets the agent keep talking while a tool runs in the background. [Source](https://livekit.com/blog/async-tools-voice-agents) [Source](https://docs.livekit.io/agents/logic/tools/async/)
- **macOS/Apple Silicon:** No specific macOS/Apple Silicon caveats or confirmations were found in the sources checked.
- **Client options:** Native SDKs for web, iOS, Android, and even microcontrollers, plus the self-hosted SIP telephony bridge described above. [Source](https://celloip.com/blog/livekit-voice-agents-guide/)

## 3. TEN Framework (TEN-framework/ten-framework)

- **Repo/stars/license/language:** github.com/TEN-framework/ten-framework — ~11.2k stars, ~1.4k forks, Apache License 2.0 "with additional restrictions" (per repo LICENSE), core in C++, agent dev in Python, frontend in JS/TS, API server in Go. [Source](https://github.com/TEN-framework/ten-framework)
- **Maintenance:** 2,101+ commits; release history shows active, frequent releases (0.11.68 → 0.11.74 across roughly July–October 2026), with one source characterizing it as releasing "roughly every two weeks, commits landing daily." [Source](https://github.com/TEN-framework/ten-framework/releases)
- **Company backing/community:** Backed by Agora (real-time communication infrastructure company); Agora's own site hosts a TEN Framework page. Contributors listed include kimdwkimdw, halajohn, YiminW, sunxilin, FaithfulinLOVE, diyuyi-agora, among others. A TEN Community Discord exists. One source noted the project "celebrates one year anniversary" (per a Reuters/TradingView wire item dated Nov 2025), suggesting the project launched publicly around late 2024/2025. [Source](https://www.agora.io/en/open-source/ten-framework/) [Source](https://de.tradingview.com/news/reuters.com,2025-11-02:newsml_NFC6ZfHY7:0-ten-framework-celebrates-one-year-anniversary-as-open-source-infrastructure-for-real-time-conversational-ai-development)
- **Transports:** Agora RTC (real-time communication), WebSocket connections, and SIP/Twilio for phone calls. [Source](https://github.com/TEN-framework/ten-framework)
- **Local STT/TTS:** Documented STT providers include Deepgram, Azure, and **Whisper** ("allowing you to use Whisper as your speech-to-text engine locally"), with the extension system letting you "switch from Deepgram to Whisper" by changing one line. Documented TTS providers found include ElevenLabs and OpenAI; I did not find explicit first-party documentation for fully local TTS engines (Piper/Kokoro/XTTS) in TEN — only Whisper STT was confirmed as a documented local option. Extensions can be written in C++, Go, or Python and run in the same process. [Source](https://github.com/TEN-framework/ten-framework)
- **Local VAD/turn detection:** **TEN VAD** — a dedicated low-latency, lightweight, high-performance streaming VAD, cross-platform in C with support for Linux x64, Windows, macOS, Android, and iOS, plus Python bindings and WASM for web; a universal macOS binary (`ten_vad.framework`) supports both arm64 (Apple Silicon) and x86_64 (Intel). TEN also ships a dedicated Turn Detection component for full-duplex dialogue. [Source](https://github.com/ten-framework/ten-vad) [Source](https://deepwiki.com/TEN-framework/ten-vad/7.2.2-building-examples-for-macos)
- **LLM architecture/pluggability:** The extension/plugin system is explicitly designed to let you "swap components like Lego blocks," with extensions in C++, Go, or Python; this strongly implies an arbitrary-code LLM extension is supported, though I did not find a specific documented class/interface name (e.g., an `LLMExtension` base class) comparable to Pipecat's `LLMService` or LiveKit's `llm` module — this is a gap to flag for follow-up against TEN's extension API docs at theten.ai.
- **Interruption/filler/background speech:** Not independently confirmed with primary-source detail beyond the general "Turn Detection for full-duplex dialogue" and VAD capability listed in the repo description; no specific filler-speech or background-task API documentation was found in the sources retrieved.
- **macOS/Apple Silicon:** Confirmed via TEN VAD — universal macOS binary covering arm64 (Apple Silicon) and x86_64 (Intel); build script `build-and-deploy-mac.sh` defaults to `ARCH=arm64`. [Source](https://deepwiki.com/TEN-framework/ten-vad/7.2.2-building-examples-for-macos)
- **Client options:** Agora RTC-based real-time clients, WebSocket clients, SIP/Twilio telephony bridging; also lists avatar/lip-sync integrations (Live2D, HeyGen, Tavus, Trulience) and ESP32-S3 hardware integration as notable examples, suggesting an embedded/IoT client path in addition to standard web/telephony. [Source](https://github.com/TEN-framework/ten-framework)

## 4. Vocode (vocodedev/vocode-core, formerly vocode-python)

- **Repo/stars/license/language:** github.com/vocodedev/vocode-core — ~3.8k stars, MIT license, Python (Poetry-based). Note: the originally-named `vocode-python` repo structure now lives under `vocode-core`; a separate fork `ScaleVoice/vocode-python` was archived by its owner on 2024-05-17 (that archive notice applies to the fork, not necessarily the canonical repo). [Source](https://github.com/vocodedev/vocode-core) [Source](https://github.com/ScaleVoice/vocode-python)
- **Maintenance status — stale:** Latest PyPI stable release is **0.1.113, dated 2024-06-17**; most recent repo activity found (pre-release tags) runs through 2024-08-07 (v0.1.114a2); one search summary stated the last code push to main was in November 2024. The project is **not formally archived** but is **effectively unmaintained** as of October 2026 — no releases or confirmed commits in roughly two years. The Vocode marketing site reportedly redirects to GitHub, consistent with the hosted product being wound down; the project has publicly stated it is seeking community maintainers. [Source](https://pypi.org/pypi/vocode/json) [Source](https://github.com/vocodedev/vocode-core/releases)
- **Transports:** System audio (local device) conversations, inbound/outbound phone calls, Zoom dial-in. No WebRTC transport was found documented (its real-time story is built around telephony/system-audio rather than browser WebRTC). [Source](https://github.com/vocodedev/vocode-core)
- **Local STT:** Documented support includes **Whisper** and **Whisper.cpp** (listed explicitly alongside AssemblyAI, Deepgram, Gladia, Google Cloud, Azure, RevAI as STT backends). [Source](https://github.com/vocodedev/vocode-core)
- **Local TTS:** Documented local/self-hostable-leaning options include **Coqui ("Coqui" listed in TTS integrations)** and **Bark**; also gTTS, StreamElements, plus hosted options (Rime.ai, Azure, Google Cloud, Play.ht, ElevenLabs, Cartesia, AWS Polly). [Source](https://github.com/vocodedev/vocode-core)
- **Local VAD/turn detection:** VAD and turn-taking are handled via "punctuation-based endpointing configuration" per repo description — this is a simpler heuristic/endpointing approach rather than a dedicated ML VAD or turn-detection model like Pipecat's Smart Turn or LiveKit's turn-detector. No Silero VAD or equivalent was confirmed as integrated. [Source](https://github.com/vocodedev/vocode-core)
- **LLM architecture/pluggability:** Supports OpenAI and Anthropic directly as documented LLM providers; for local/custom LLMs the common integration pattern found is routing through an OpenAI-compatible endpoint (e.g., Ollama's OpenAI-compatible API at `localhost:11434/v1`) rather than a confirmed, dedicated "local LLM" base class. Vocode also integrates with Langchain agents. I could not confirm a specific documented "BaseAgent" subclassing pattern for arbitrary custom LLM logic from primary Vocode sources — this should be treated as unconfirmed/a gap, not a documented feature.
- **Interruption/filler/background speech:** No primary-source documentation on interruption/barge-in handling, filler speech, or background task support was found for Vocode in this research pass — flagged as an explicit gap (search results focused on STT/TTS/LLM provider lists and maintenance status, not these specific runtime behaviors).
- **macOS/Apple Silicon:** No specific macOS/Apple Silicon notes were found.
- **Client options:** No dedicated browser WebRTC or native mobile SDK was found; its primary "client" integrations are telephony (phone calls) and Zoom dial-in, plus local system-audio conversations for testing/dev.
- **Community/maintenance health:** 754 commits on main; contributor count not found in available sources; the project explicitly describes itself as seeking community maintainers, a strong signal of reduced organizational backing/maintenance health compared to the other three frameworks. [Source](https://github.com/vocodedev/vocode-core)
