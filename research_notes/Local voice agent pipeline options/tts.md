# Local Text-to-Speech Models for Low-Latency Conversational Voice Agents (Apple M1 8/16GB, RTX 3070 8GB)

## Which models achieve <200-300ms time-to-first-audio with streaming on each target hardware, and which only work in batch mode?

### Takeaway
Several sub-2B-parameter models now advertise genuine incremental text-in/audio-out streaming with sub-300ms TTFA on GPU-class hardware (Kyutai TTS 1.6B ~220ms, Chatterbox-Turbo ~75-200ms, VibeVoice-Realtime-0.5B ~300ms, Orpheus ~100-200ms with tuned buffering, Sesame CSM-1B ~50-400ms depending on implementation). On an RTX 3070 (8GB) most of these should hit target. On Apple M1 (no dedicated GPU, shared/slower memory bandwidth), only lightweight CPU/Metal-native paths (Kokoro via mlx-audio/CoreML, Piper, Kitten TTS, MeloTTS, Kyutai Pocket-TTS) are confirmed fast; larger streaming LLM-TTS models (Orpheus 3B, Dia2-2B, Higgs Audio) have no M1-specific latency benchmarks found and likely fall outside the 200-300ms budget on an M1's weaker compute. Batch-only (whole-utterance synthesis, no incremental token streaming) models include Kitten TTS Nano/Mini (confirmed: "requires full audio synthesis before playback with no streaming output," FTTS ~10,483ms) and apparently XTTS-v2 in many deployments (streams audio chunks but not incremental text ingestion the way Kyutai's delayed-streams design does).

### Cited Findings
- Kokoro-82M on GPU: RTX 4060 Ti RTF 0.03, RTX 3090 RTF 0.02, RTX 5090 RTF 0.01; first-audio latency 25ms (RTX 6000 PRO) to 85ms (RTX 3050) — [GIGAGPU TTS Latency Benchmarks](https://gigagpu.com/tts-latency-benchmarks/)
- Kokoro end-to-end TTFA (with network) p50 158ms / p95 196ms; full-utterance TTLB p50 696ms / p95 1025ms — [GIGAGPU TTS Latency Benchmarks](https://gigagpu.com/tts-latency-benchmarks/) (hardware for this specific figure not fully specified in excerpt — treat as directional)
- Kokoro on Apple M3 Pro CPU: 22-second paragraph rendered in 3.5s (~RTF 0.16) — [Brian Tung blog](https://briantung.me/blog/tts-engines-in-the-browser/)
- Kokoro via mlx-audio on M4 Max: short replies 0.076s / RTF 0.019, vs ONNX CPU 0.4s / RTF 0.15 (MLX ~5-8x faster than ONNX CPU) — [xugj520.cn MLX-Audio](https://www.xugj520.cn/en/archives/mlx-audio-apple-silicon-tts-optimization.html)
- CoreML Kokoro builds are 1.6-2.3x faster than mlx-audio 0.4.3 across M-series; M2 Studio synthesizes 30s of audio in 379ms; **M1 Mini (base, presumably 8GB) in 1,959ms** for 30s of audio — [kakoo GitHub issue #23](https://github.com/ragaeeb/kakoo/issues/23)
- MetalRT (specialized inference engine) claims 2.8x speedup vs mlx-audio on short phrases: 178ms for 4-word responses vs 493ms for mlx-audio — [RunAnywhere MetalRT blog](https://www.runanywhere.ai/blog/metalrt-speech-fastest-stt-tts-apple-silicon) (vendor-authored benchmark; treat with caution)
- Piper: general RTF ~0.2; a Dec 2025 arXiv study measured RTF 0.153 on a 12th Gen Intel i7-1255U CPU-only; runs real-time on Raspberry Pi 5 CPU alone and ~10x real-time on modern desktop CPU — [Cekura Piper TTS](https://www.cekura.ai/discover/piper-tts), [piper1-gpl docs](https://github.com/OHF-Voice/piper1-gpl)
- Orpheus TTS: ~200ms TTFA with batched generation, ~100ms with input streaming on RTX-class hardware via orpheus-cpp/llama.cpp; on M3/M4 expect 1.5-4x real-time generation with Q4_K_M quantization — [orpheus-cpp GitHub](https://github.com/freddyaboulton/orpheus-cpp)
- Orpheus-cpp default pre-buffers 1.5s of audio before yielding first chunk (trades TTFA for smoothness); `pre_buffer_size` is configurable to reduce TTFA — [orpheus-cpp GitHub](https://github.com/freddyaboulton/orpheus-cpp)
- Chatterbox-Turbo (350M params): Resemble AI quotes ~75ms latency and ~6x faster-than-real-time inference on a single GPU; described elsewhere as "sub-200ms latency" — [Lior Alexander/X via search aggregation](https://x.com/LiorOnAI/status/2015137819996414453), [Communeify blog](https://www.communeify.com/en/blog/resemble-ai-chatterbox-turbo-opensource-tts-realism-performance/)
- Kyutai TTS 1.6B (~2B per some sources): streaming latency ~220ms; can serve 32 concurrent users on a single NVIDIA L40 GPU with latency under 350ms; trained on 2.5M hours; begins generating speech after only a few input words via delayed streams modeling — [Kyutai official](https://kyutai.org/tts/), [inferless GitHub](https://github.com/inferless/kyutai-tts-1.6b)
- Sesame CSM-1B: streaming latency reported as ~50-150ms in some sources, but "has no native streaming" and generates complete chunks rather than true token-by-token streaming per other sources; Vogent's production implementation generates audio within 200-400ms — [Vogent docs](https://docs.vogent.ai/platform-overview/voices/sesame), [HF discussion #10](https://huggingface.co/sesame/csm-1b/discussions/10)
- F5-TTS: first-audio latency by GPU — 320ms (RTX 3050), 220ms (RTX 4060), 165ms (RTX 4060 Ti), 130ms (RTX 3090), 90ms (RTX 5090), 82ms (RTX 6000 PRO); RTF 0.14 (RTX 4060 Ti) down to 0.06 (RTX 6000 PRO), RTX 3090 at RTF 0.10; minimum GPU recommended is RTX 4060 (8GB) — [GIGAGPU TTS Latency Benchmarks](https://gigagpu.com/tts-latency-benchmarks/) (no RTX 3070-specific number found; 3070 sits between 3050 and 3090/4060 tier, so TTFA plausibly ~150-250ms but unconfirmed — gap)
- VibeVoice-Realtime-0.5B: first audible speech in ~300ms on supported hardware; uses interleaved windowed design (incremental text encoding + parallel diffusion decoding); ~0.5B LLM backbone + 340M acoustic decoder + ~40M diffusion head; 8k token context, ~10 min continuous speech without reset — [MarkTechPost](https://www.marktechpost.com/2025/12/06/microsoft-ai-releases-vibevoice-realtime-a-lightweight-real%E2%80%91time-text-to-speech-model-supporting-streaming-text-input-and-robust-long-form-speech-generation/), [HF model card](https://huggingface.co/microsoft/VibeVoice-Realtime-0.5B)
- Zonos (Zyphra, ~1.6B, transformer or hybrid Mamba2 variant): WebSocket streaming supported; on RTX 4090, latency 200-300ms with RTF above 1 (i.e., faster than real-time) — [Zyphra beta release](https://www.zyphra.com/our-work/beta-release-of-zonos-v0-1) (no RTX 3070 figure found — gap)
- Kitten TTS Nano: INT8-quantized, 42MB, 320MB peak memory, but "requires full audio synthesis before playback with no streaming output," resulting in FTTS of 10,483ms — batch-only, disqualifying for low-latency conversational use despite tiny size — [GetStream.io on-device TTS blog](https://getstream.io/blog/best-on-device-tts-models/)
- Apple AVSpeechSynthesizer: first buffer rendered in ~20-30ms after warm-up at app launch; legacy `say` CLI spawn takes 0.8-2.0s per invocation (process spawn overhead, not representative of in-app API) — [Medium: Why AVSpeechSynthesizer Sounds Terrible](https://medium.com/@info_4533/why-avspeechsynthesizer-sounds-terrible-on-real-iphones-eb4565862ea8)

### Inferences
- On RTX 3070 (8GB), Chatterbox-Turbo, Kyutai TTS 1.6B, VibeVoice-Realtime-0.5B, Orpheus (tuned buffer), and F5-TTS (likely, interpolating between 3050/4060/3090 figures) should all land under or near the 200-300ms TTFA target with proper streaming configuration.
- On Apple M1 (CPU/Metal only, no CUDA), the only well-evidenced low-latency path is Kokoro-82M through mlx-audio or a CoreML build; the M1 Mini 30s-synthesis figure (1,959ms) implies roughly 65ms/second-of-audio, which for a typical short conversational utterance (3-5s) suggests TTFA in the 150-350ms range depending on chunking — plausible but not a directly measured TTFA statistic.
- Large streaming LLM-TTS stacks (Orpheus 3B, Dia2, Higgs Audio, VibeVoice non-realtime) are GPU-first designs; their latency claims are sourced from CUDA hardware and should not be assumed to transfer to M1 without dedicated MLX/CoreML ports, which (apart from Kokoro) do not appear to exist yet for most of these.

### Gaps
- No RTX 3070-specific TTFA/RTF benchmark found for F5-TTS, Zonos, Chatterbox (any variant), Kyutai TTS, VibeVoice-Realtime, or Dia2 — all available GPU numbers are for 3050/4060/4090/3090/5090/6000 PRO/L40/A100, requiring interpolation.
- No Apple Silicon (M1/M2/M3/M4) latency numbers found at all for Orpheus 3B via MLX, Chatterbox, Kyutai TTS 1.6B, Sesame CSM-1B, F5-TTS, Dia2, Zonos, VibeVoice, Higgs Audio, or Spark-TTS — these ecosystems appear CUDA/Linux-centric with no confirmed native Apple Silicon streaming path as of the search date.
- No M1-8GB-specific figures (only M1 Mini, unclear if base 8GB or 16GB variant) and no M2/M3/M4 comparison baseline was cross-checked against the exact M1 chip for Kokoro.

## Quality vs. latency trade-offs: which gives the most "human phone call" feeling while remaining real-time on 8GB?

### Takeaway
Among models that are both confirmed real-time on 8GB-class hardware and streaming-capable, Chatterbox (base and Turbo) and Kokoro-82M currently have the strongest naturalness evidence (TTS Arena / UTMOS scores near or above XTTS-v2), while Sesame CSM-1B is widely cited anecdotally as the most "human phone call"-like but has weaker, more mixed streaming-latency evidence and no formal Arena/MOS number found. VibeVoice-Realtime and Kyutai TTS 1.6B trade a bit of peak naturalness for more robust, officially-measured low-latency streaming behavior.

### Cited Findings
- TTS Arena leaderboard snapshot (source uncertain on date/methodology — appears to blend differing scales): Kokoro ranks #1 with naturalness 4.8/5; CosyVoice 2 #2 at 4.26/5; Chatterbox #3 at 4.7/5 — [aivideosensei comparison](https://aivideosensei.com/compare/kokoro-vs-chatterbox-vs-xtts) (secondary aggregator, not the primary TTS Arena site itself — treat cautiously)
- Separate Elo-based TTS Arena figures: Kokoro Elo ~1056-1057, 54.4% win rate across 5,000+ matchups; briefly held outright #1 in January 2026 — [search aggregation, primary source likely huggingface.co/spaces/TTS-AGI/TTS-Arena] (URL not directly captured — gap)
- tts-bench UTMOS (predicted naturalness) scores: Chatterbox 4.423, Chatterbox Turbo 4.274, Kokoro 4.302 — [tts-bench scores](https://5uck1ess.github.io/tts-bench/scores.html)
- Separate human-MOS evaluation: XTTS achieved highest overall human MOS at 3.71, leading on clarity, with strong prosody/pronunciation scores — [source aggregated via search, exact paper/page not captured — gap]
- Open-weight-only ranking on Artificial Analysis / Voice Arena (broader market, not all candidates covered): Fish Audio Drama 3 Preview (Elo 1240), Breeze TTS 2 (1228), Ming-3.0-tts (1187), Fish Audio S2 Pro (1109), Step Audio EditX (1099) lead among 92 total models, of which only 16 are open-weight — [Artificial Analysis TTS Leaderboard](https://artificialanalysis.ai/text-to-speech/leaderboard) — none of our named 8GB-friendly candidates (Kokoro, Chatterbox, Piper, etc.) appear in this top-5 open-weight slice, suggesting this leaderboard emphasizes larger/cloud-hosted open-weight models rather than small conversational-latency models
- Sesame CSM-1B: "the voice generally surpassing state-of-the-art voice vendors in realism, while beating them on cost and latency" per vendor-adjacent blog; voice cloning from 8-20 seconds via context-prompt approach rather than zero-shot — [Vogent blog](https://blog.vogent.ai/posts/build-ultrarealistic-voice-agents-with-sesame) (vendor-published, not independently verified against Arena)
- Dia2 (Nari Labs, Apache 2.0): markets non-verbal tags (laughs, coughs, gasps), multi-speaker [S1]/[S2] conversational tags, voice-cloning-via-sample, pitched as improving "smoother prosody, more natural-sounding intonation" over Dia 1.6B — [dia-tts.com Dia2-2B page](https://dia-tts.com/dia2-2b), [HF nari-labs/Dia2-2B](https://huggingface.co/nari-labs/Dia2-2B) (no independent MOS/Arena score found for Dia2 — gap)

### Inferences
- For "most human phone call feel" specifically (prosody, breathing, disfluency, emotional nuance) at real-time speed on 8GB, the strongest combination of evidence points to Chatterbox (emotion control, high UTMOS, MIT-licensed, confirmed low-latency Turbo variant) or Kokoro (highest blind-preference naturalness among lightweight models, but less expressive/emotional than Chatterbox or Dia2 by design — it's a StyleTTS2-derived single-pass model, not built for conversational emotion tags).
- Sesame CSM-1B's qualitative reputation for realism is strong but is not yet backed by a comparable independent Arena/MOS figure in the evidence gathered, and its streaming behavior is inconsistently characterized across sources (some say near-native streaming, others say it lacks true native streaming) — this is a genuine open question, not just a sourcing gap.

### Gaps
- No single benchmark run was found that directly compares Chatterbox, Kokoro, Sesame CSM-1B, Dia2, VibeVoice-Realtime, and Kyutai TTS on the same prompts/raters — all figures come from different studies with different scales (UTMOS 1-5, Elo, human MOS 1-5), making direct ranking across all candidates unreliable.
- No Arena or MOS figure found for Dia2, Spark-TTS, Higgs Audio, Zonos, or NeuTTS Air.

## Memory budget when sharing the GPU/unified memory with STT (e.g. Whisper/Parakeet) — which combos fit in 8GB?

### Takeaway
On an 8GB RTX 3070, Whisper large-v2/v3 (fp16, beam 5) alone uses ~4.5GB VRAM (or ~2.9GB at int8), leaving only 1-3GB free for TTS and the LLM — not enough to also host fp16 Kokoro, F5-TTS, or XTTS-v2 comfortably. A full local voice-agent stack (STT + LLM + TTS) realistically needs more than 8GB unless models are aggressively downsized/quantized; practical 8GB-fitting combos pair a smaller/quantized STT (Whisper base/small, or NVIDIA Parakeet TDT 0.6B at ~1GB) with a small TTS (Kokoro-82M, Chatterbox-Turbo 350M, Piper) and a small quantized LLM (~3B).

### Cited Findings
- Whisper large-v2 at fp16 with beam size 5 uses 4,525MB VRAM; at int8, 2,926MB — both measured on an 8GB RTX 3070 Ti — [localaimaster VRAM by GPU](https://localaimaster.com/blog/voice-ai-vram-requirements-by-gpu)
- "At 8GB (RTX 3070), you can run large-v2/v3 fp16 with beam 5, but TTS models like Kokoro, F5-TTS, and XTTS-v2 cannot be resident alongside fp16 Whisper" — [localaimaster VRAM by GPU](https://localaimaster.com/blog/voice-ai-vram-requirements-by-gpu)
- "A voice agent pipeline typically runs Whisper + LLM + TTS on one card, and those combined VRAM needs push you toward 24GB minimum" for comfortable headroom — [localaimaster VRAM by GPU](https://localaimaster.com/blog/voice-ai-vram-requirements-by-gpu)
- Parakeet TDT 0.6B uses approximately 1GB VRAM — comparatively lightweight — [search aggregation, source: localaimaster/northflank cluster, exact URL not isolated — gap]
- Realistic 8GB configuration suggested: "llama3.2:3b + Whisper base/small with limited headroom for other services" — [localaimaster VRAM by GPU](https://localaimaster.com/blog/voice-ai-vram-requirements-by-gpu)
- F5-TTS: ~500M parameters (one source says 336M), ~2-3GB VRAM at FP16; minimum GPU recommendation RTX 4060 (8GB), with RTX 3090 (24GB) recommended for production — [runpod F5-TTS guide](https://www.runpod.io/articles/guides/f5-tts-on-runpod), [GIGAGPU](https://gigagpu.com/tts-latency-benchmarks/)
- Higgs Audio V2 full (3B params) requires at least an RTX 4090; Higgs Audio V2.5 (1B params) runs comfortably on 8GB+ VRAM GPUs — [search aggregation via llmreference/modal cluster — exact URL for this specific stat not isolated, gap]
- Chatterbox-Turbo (350M) explicitly marketed as having "less compute and VRAM" than prior Chatterbox variants, intended for single-GPU low-latency voice agents — [Communeify Chatterbox-Turbo blog](https://www.communeify.com/en/blog/resemble-ai-chatterbox-turbo-opensource-tts-realism-performance/)

### Inferences
- The most realistic 8GB RTX 3070 conversational stack: Whisper small/base or Parakeet TDT 0.6B (STT, ~1-2GB) + a 3-4B quantized LLM (~2-3GB) + Chatterbox-Turbo or Kokoro-82M (TTS, likely <1-2GB given their small parameter counts) — this should fit within 8GB with modest headroom, whereas swapping in Whisper large-v2/v3 fp16 or F5-TTS/XTTS-v2 at full precision risks exceeding the budget once the LLM is also loaded.
- No source gave an exact resident-VRAM figure for Kokoro-82M or Chatterbox-Turbo in isolation (only relative/qualitative "lightweight" claims), so precise headroom math for an 8GB card remains an estimate, not a confirmed figure.

### Gaps
- No source gives an exact MB/GB resident VRAM figure for Kokoro-82M, Chatterbox (any variant), Piper, Sesame CSM-1B, Kyutai TTS 1.6B, Zonos, Dia2, or VibeVoice-Realtime in isolation — all VRAM claims found were either about STT (Whisper/Parakeet) or generic/relative ("lightweight," "less VRAM than previous models") for TTS.
- No source directly tested a concurrent STT+LLM+TTS resident-memory combination on an actual 8GB RTX 3070 (the "24GB minimum" claim is for comfortable headroom running everything unconstrained, not a hard floor — it isn't a tested 8GB failure case).
- No Apple Silicon unified-memory equivalent breakdown (e.g., "Whisper + Kokoro resident on M1 8GB") was found — unified memory sharing dynamics on Mac (where RAM is shared with the whole OS, not a dedicated VRAM pool) were not covered in any source retrieved.

## Which are well integrated into voice frameworks (Pipecat, LiveKit Agents, RealtimeTTS, Speaches) already?

### Takeaway
Pipecat ships first-class, in-process local TTS services for Piper and XTTS (among others: Whisper, Moonshine, Funasr for STT, plus "Pocket TTS") and has roughly 70 Python integrations; LiveKit Agents has a comparable ~72 Python / 37 Node plugin surface but tends to point at an OpenAI-compatible server endpoint rather than running models in-process. RealtimeTTS exposes a standard engine/REST abstraction that can be wired into either framework as a custom TTS stage. No primary-source confirmation was found in this pass for native Kokoro, Chatterbox, Kyutai TTS, Sesame CSM, Dia2, or VibeVoice integrations in Pipecat/LiveKit's official plugin lists, nor coverage of Speaches at all — these are gaps, not negatives.

### Cited Findings
- "Pipecat supports running service classes with models in-process, including locally-downloaded models like Whisper, Piper, XTTS, Moonshine, Funasr, and Pocket TTS. Pipecat packages these local, in-process runners as first-class services, while LiveKit points an OpenAI-compatible client at a server you run." — [LiveKit blog: best open source frameworks](https://livekit.com/blog/best-open-source-voice-and-video-ai-agent-frameworks)
- "Pipecat has around 70 integrations on the Python side, while LiveKit has around 72 plugins in Python and 37 in Node. Both frameworks cover the same major STT, LLM and TTS vendors, and both accept OpenAI Realtime, Gemini Live and other speech-to-speech models in place of the assembled pipeline." — [LiveKit blog: best open source frameworks](https://livekit.com/blog/best-open-source-voice-and-video-ai-agent-frameworks)
- "RealtimeTTS exposes a standard REST API that slots into any of them [Vapi, Pipecat, LiveKit] as the TTS provider. With Pipecat, you write a custom service class that calls the Realtime TTS API in the TTS stage of your pipeline, as Pipecat's plugin architecture is designed for this pattern, with the TTS endpoint accepting text and returning streaming audio." — [LiveKit blog: best open source frameworks](https://livekit.com/blog/best-open-source-voice-and-video-ai-agent-frameworks)
- A community tutorial exists for "LiveKit + Piper TTS: Building a Low-Latency, Local Voice Agent (with Real-Time Latency Tracking)" demonstrating Piper is usable in LiveKit pipelines in practice, even if not an official first-party plugin — [Medium tutorial](https://medium.com/@mail2chasif/livekit-piper-tts-building-a-low-latency-local-voice-agent-with-real-time-latency-tracking-92a1008416e4)

### Inferences
- Piper and XTTS appear to be the most framework-mature local TTS choices today (explicit Pipecat first-class support, community LiveKit recipes), which is a practical advantage even though XTTS-v2's CPML license blocks commercial use and Piper is GPL-3.0 (see license section below) and lower in naturalness than Kokoro/Chatterbox.
- The newer, higher-naturalness/lower-latency candidates (Kokoro, Chatterbox, Kyutai TTS, Sesame CSM, Dia2, VibeVoice) likely require a custom service wrapper in Pipecat or LiveKit today (following the same pattern RealtimeTTS uses) rather than drop-in official support — this is an inference from the "custom service class" pattern described for RealtimeTTS, not a confirmed statement about these specific models.

### Gaps
- No information found on Speaches (a speech-serving framework named in the research request) at all — searches did not surface primary documentation or integration notes for it in this pass.
- No confirmation found of official/first-party Pipecat or LiveKit Agents plugins for Kokoro-82M, Chatterbox, Kyutai TTS, Sesame CSM-1B, Dia2, Zonos, Higgs Audio, VibeVoice, NeuTTS Air, Marvis TTS, Kitten TTS, or MeloTTS — these may well exist (several of these projects are popular enough to likely have community packages) but were not found as primary-sourced facts in this research pass.
- RealtimeTTS's own GitHub repo/engine list was not directly fetched — the characterization above comes from a secondary LiveKit blog post, not RealtimeTTS's own documentation.

## Supplementary: Model-by-model reference data gathered

### Takeaway
This section consolidates per-model specs (params, license, language support, maintenance) gathered across the research that didn't fit neatly under the four key questions above, to give the report-writer a quick-reference table's worth of raw material.

### Cited Findings
- **Kokoro-82M**: 82M parameters, StyleTTS2-derived architecture with ISTFTNet vocoder; built on Apache 2.0-licensed StyleTTS2 base, Kokoro itself commonly cited as Apache 2.0 (the German fine-tunes — kikiri-tts — are explicitly noted as Apache 2.0) — [search aggregation: xugj520.cn], [soniqo German Kokoro issue](https://github.com/hexgrad/kokoro/issues/186). Note: StyleTTS2's own license is described elsewhere as "MIT license with conditions... muddier than the MIT label suggests" — [modal.com blog aggregation]. German support exists only via two separate single-voice community fine-tunes (dm_martin, df_victoria), not the core multilingual bundle — [soniqo Kokoro voices guide](https://soniqo.audio/guides/kokoro). Kokoro supports 15+ languages overall including English, Japanese, Spanish, French, German, Chinese, Korean — [soniqo guide](https://soniqo.audio/guides/kokoro).
- **Piper / OHF-Voice/piper1-gpl**: Original rhasspy/piper repo archived October 2025; actively maintained successor is OHF-Voice/piper1-gpl, run by the Open Home Foundation (the Home Assistant voice-stack nonprofit) — license is GPL-3.0 (changed from the original more permissive terms) — [Grokipedia Piper page](https://grokipedia.com/page/Piper_text-to-speech_system), [piper1-gpl GitHub](https://github.com/OHF-Voice/piper1-gpl). A community fork, piper-plus, adds CUDA/CoreML/DirectML and 6 languages (JA/EN/ZH/ES/FR/PT) with streaming — [ayutaz piper-plus GitHub](https://github.com/ayutaz/piper-plus).
- **Orpheus TTS**: canopyai/Orpheus-TTS, 3B base (smaller distillations exist); llama.cpp/vLLM backends available via orpheus-cpp — [canopyai GitHub](https://github.com/canopyai/Orpheus-TTS).
- **Chatterbox family (Resemble AI)**: MIT license, commercial use explicitly permitted; variants are Chatterbox (500M, "original," creative emotion controls), Chatterbox-Turbo (350M, low-latency, English-focused, distilled decoder from 10 steps to 1), Chatterbox-Nano (110M), Chatterbox Multilingual V3 (0.5B, 21 languages + 4 dialect variants, 6 more as separate language packs) — [codersera Chatterbox Turbo](https://codersera.com/blog/chatterbox-turbo-run-and-install-locally-free-elevenlabs-alternative-2026/), [Communeify](https://www.communeify.com/en/blog/resemble-ai-chatterbox-turbo-opensource-tts-realism-performance/). Includes an inaudible PerTh neural watermark on all generated audio designed to survive MP3 compression — [techpilot.ai](https://techpilot.ai/tools/chatterbox/). No explicit confirmation found of German being in the Multilingual V3 language list (gap).
- **F5-TTS**: ~500M params per one source, 336M per another (sources conflict); ~2-3GB VRAM at FP16; Apache-licensed per SWivid/F5-TTS GitHub convention (exact license text not independently re-verified in this pass — treat as likely-Apache/MIT-family but unconfirmed) — [SWivid/F5-TTS GitHub](https://github.com/SWivid/F5-TTS).
- **Kyutai TTS**: Two distinct projects with different licenses — (1) the main "delayed streams modeling" research models (kyutai-labs/delayed-streams-modeling, ~1.6B/2B) are Apache-2.0; (2) Pocket-TTS (a separate, smaller CPU-focused model) is MIT for both code and weights. Pocket-TTS supports English, French, German, Portuguese, Italian, Spanish, with larger 24-layer variants (e.g. `german_24l`) for higher quality at lower speed — [kyutai-labs/pocket-tts GitHub](https://github.com/kyutai-labs/pocket-tts), [HF kyutai/pocket-tts](https://huggingface.co/kyutai/pocket-tts). The main 1.6B/2B streaming model's own language support in the sources gathered is cited as English and French specifically — [Kyutai official](https://kyutai.org/tts/) — so German support for low-latency *streaming* Kyutai TTS specifically (not Pocket-TTS) is a gap/unclear.
- **Sesame CSM-1B**: voice cloning via context-prompt (reference utterances), not zero-shot, from ~8-20 seconds of audio — [Vogent docs](https://docs.vogent.ai/platform-overview/voices/sesame). License and language support not captured in this pass (gap).
- **XTTS-v2 (Coqui / idefix / coqui-tts)**: Coqui Inc. shut down January 2024; the toolkit code (Python package, CLI, training code) is MPL-2.0 (permissive, commercial-use-friendly with source-disclosure conditions on toolkit modifications), maintained in a community fork by the Idiap Research Institute under the `coqui-tts` package name. The XTTS-v2 *model weights* specifically are under the Coqui Public Model License (CPML) 1.0.0, which is non-commercial only — and because Coqui Inc. no longer exists, there is no commercial licensing path available at all — [coqui-ai/TTS GitHub discussion #4304](https://github.com/coqui-ai/TTS/discussions/4304), [localaimaster XTTS commercial license](https://localaimaster.com/blog/xtts-coqui-commercial-license). No reference to "idefix" specifically as a fork name was found — this may be a misremembered or very new/niche fork name (gap).
- **Dia2 (Nari Labs)**: 1B and 2B checkpoints (Dia2-1B, Dia2-2B), both Apache 2.0, on Hugging Face (nari-labs/Dia2-1B, nari-labs/Dia2-2B); supports up to ~2 minutes of English speech per generation; streaming architecture that begins synthesizing from the first few tokens; [S1]/[S2] multi-speaker tags and non-verbal cue tags (laughs, coughs, gasps); voice cloning via uploaded sample — [HF nari-labs/Dia2-2B](https://huggingface.co/nari-labs/Dia2-2B), [dia-tts.com](https://dia-tts.com/dia2-2b). English-only confirmed; no German support found (gap/likely absent).
- **Zonos (Zyphra)**: v0.1 beta (Feb 2025), ~1.6B params, two variants (pure transformer and hybrid Mamba2 state-space); Apache 2.0 license (notably permissive vs. competitors); WebSocket streaming API; 200-300ms latency at RTF>1 on RTX 4090 — [Zyphra beta release blog](https://www.zyphra.com/our-work/beta-release-of-zonos-v0-1). Note a "ZONOS2" product also surfaced in search results (tech-insider.org) suggesting a newer version exists but was not independently verified in this pass (gap).
- **VibeVoice-Realtime-0.5B (Microsoft)**: ~0.5B parameter Qwen2.5-based LLM backbone + 340M acoustic decoder + ~40M diffusion head; 8k token context; ~10 minutes continuous speech without reset; license and non-realtime VibeVoice sibling's language support not captured in this pass (gap).
- **Higgs Audio (Boson AI)**: v2 (July 2025, Apache 2.0) has a full 3B-param model requiring at least an RTX 4090, and a lighter V2.5 (1B params) that "runs comfortably on 8GB+ VRAM GPUs." v3 (June 2026) is 4B params, 102 languages, zero-shot cloning, 21 emotion control tokens, but licensed under the "Boson Higgs Audio v3 Research and Non-Commercial License" — commercial/hosted/revenue-generating use requires a separate paid license; no official VRAM figure published for v3, estimated 12-16GB for a 4B model — [LMSYS blog](https://www.lmsys.org/blog/2026-06-04-higgs-audio-v3-tts/), [boson-ai/higgs-audio GitHub](https://github.com/boson-ai/higgs-audio).
- **StyleTTS2**: English-only weights; Elo 892 in one cited comparison; license described as "MIT... with conditions," muddier than a plain MIT label implies — [modal.com blog aggregation, exact quote source page not independently isolated — gap].
- **Spark-TTS**: Apache 2.0, multiple parameter sizes including a 0.5B variant seen in Hugging Face repos (e.g. Vi-SparkTTS-0.5B); full official spec sheet not retrieved in this pass (gap).
- **Kitten TTS**: Family ranges 15M-80M params (25-80MB on disk): kitten-tts-mini (80M, 80MB), kitten-tts-micro (40M, 41MB), kitten-tts-nano (15M). English-only, no voice cloning mentioned, batch-only synthesis (no streaming output), FTTS ~10,483ms for the INT8 nano variant — disqualifying for conversational low-latency use despite CPU-friendliness — [KittenML/KittenTTS GitHub](https://github.com/KittenML/KittenTTS), [GetStream.io blog](https://getstream.io/blog/best-on-device-tts-models/).
- **NeuTTS Air**: 0.7B params, on-device voice cloning from as little as 3 seconds of reference audio (3-15s recommended); English-only; smaller "NeuTTS Nano" sibling variants add French, German, Spanish — [GetStream.io blog](https://getstream.io/blog/best-on-device-tts-models/).
- **Marvis TTS**: Built on CSM-1B; clones voices from 10 seconds of reference audio; English-only "for now" — [GetStream.io blog](https://getstream.io/blog/best-on-device-tts-models/).
- **MeloTTS**: Fast enough for real-time CPU inference; five English accents plus five other languages — [GetStream.io blog](https://getstream.io/blog/best-on-device-tts-models/) (German inclusion among the "five other languages" not confirmed — gap).
- **macOS native (AVSpeechSynthesizer / `say`)**: AVSpeechSynthesizer renders first buffer in ~20-30ms after app-launch warm-up (in-process API); the `say` CLI has 0.8-2.0s per-invocation overhead (process spawn, not representative of the underlying synthesis speed); Apple's highest-quality on-device neural voice tier is called "Super-compact," matching the voices used by Siri's read-aloud feature, fully offline — [Medium: AVSpeechSynthesizer](https://medium.com/@info_4533/why-avspeechsynthesizer-sounds-terrible-on-real-iphones-eb4565862ea8). Caution noted: routing through `.spokenAudio` audio session category triggers an accessibility processing graph (hearing-aid EQ, noise reduction) that can make output sound worse — [same source].

### Inferences
- License landscape is highly split: fully commercial-friendly options include Kokoro (Apache 2.0), Chatterbox family (MIT), Kyutai Pocket-TTS (MIT) and main Kyutai models (Apache 2.0), Dia2 (Apache 2.0), Zonos (Apache 2.0), Spark-TTS (Apache 2.0), Higgs Audio v2 (Apache 2.0); GPL-copyleft (viral, commercial-use-complicating) is Piper (GPL-3.0 as of piper1-gpl); non-commercial-only/no-path-to-commercial are XTTS-v2 weights (CPML, defunct licensor) and Higgs Audio v3 (explicit non-commercial research license, paid tier required for production).
- For a privacy-conscious, commercially-deployable, low-latency German+English conversational agent, the realistic shortlist narrows to: Kokoro-82M (via two separate German fine-tunes, Apache 2.0, excellent naturalness, but batch-ish per-sentence rather than token-streaming architecture), Kyutai Pocket-TTS (native German support, MIT, but no confirmed streaming TTFA benchmark found), and Chatterbox Multilingual V3 (MIT, 21+4 languages, German inclusion unconfirmed).

### Gaps
- Confirmation of German in Chatterbox Multilingual V3's specific language list was not found (only "21 languages plus 4 dialect variants" as a count, no itemized list retrieved).
- German support for Kyutai's main streaming 1.6B/2B research model (as opposed to the separate Pocket-TTS variant) could not be confirmed one way or the other.
- Independent (non-vendor) verification of Zonos "ZONOS2," VibeVoice's non-realtime sibling's language list, and Higgs Audio v3's exact VRAM footprint were not found.
